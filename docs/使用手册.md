## 1. 登录与角色权限

### 【面向用户：操作说明】
- **入口**：浏览器打开线上地址，进入登录页；输入账号密码登录。
- **角色**：超级管理员 > 管理员 > 普通成员。
- 已登录状态下再次打开登录页，页面会提示「当前已登录」，可直接【进入系统】或【退出】。
- **限制**：账号由超级管理员在「用户管理」创建；连续输错不会锁号，但请勿把账号密码贴在公开渠道。

### 【面向 AI：开发维护提示】
- 前端：`frontend/login.html`、`frontend/js/login.js`、`frontend/js/auth.js`（`ERP.auth`）、`frontend/css/login.css`。
- 后端：`backend/app/routers/auth.py`（`POST /api/auth/login`、`GET /api/auth/me`），JWT 由 `frontend/js/api.js` 自动附带，401 自动清理会话回登录页。
- 角色校验优先在后端 `require_admin` / `require_super`（`backend/app/deps.py`）；前端 `ERP.auth.isAdmin/isSuper` 仅控制入口显隐，**不能只靠前端做权限**。
- **不能改动**：`users` 表结构、bcrypt 密码哈希规则、JWT 密钥来源（`.env`）。
- 登录页文案已接入 `ui_settings`（见第 11 节），改动文案不要写死进 HTML 默认值以外的新位置。

## 2. 工作台（仪表盘）

### 【面向用户：操作说明】
- **入口**：登录后首页 / 侧边栏【工作台】。
- 顶部 KPI：物料总种类、当期入库物料次数、当期领用物料次数、当期涉及物料条目数量。
- 右上角【统计周期】下拉：本月 / 本周 / 本季度 / 半年 / 本年 / 近 12 个月，切换后 KPI 与趋势图一起刷新。
- 【进出物料趋势】：折线图，展示每日/每月的入库与领用次数，每 15 秒自动刷新，切回页面也会刷新。
- 【物料分类占比】：环形图，**只统计一级大类**（电阻 / 电容…）的物料合计与百分比；鼠标悬停显示「分类：N 种（占比 X%）」。
- 待办、快捷入口、最近进出库记录按当前角色展示。
- **限制**：图表库为本地文件（`frontend/vendor/chart.umd.min.js`），断网也能显示；若数据为空会显示「暂无分类数据」而非空白。

### 【面向 AI：开发维护提示】
- 前端：`frontend/dashboard.html`、`frontend/js/dashboard.js`、`frontend/css/dashboard.css`；图表依赖**本地** `vendor/chart.umd.min.js`（**不要改回 CDN**，国内网络会导致图表空白）。
- 后端：`GET /api/dashboard/summary?period=`（`backend/app/routers/dashboard.py`）。
  - 入库口径 = `materials.inbound_at`（建档入库）+ `material_logs.action='restock'` 且 note **不是**初始库存流水的记录；
  - 领用口径 = `material_logs.action='borrow'`；
  - 新增字段 `new_material_count / restock_count` 可扩展使用。
- 分类占比数据来自 `GET /api/categories` 的 `tree` 根节点 `total_count`，前端 `storeCategoryRoots()` 计算；**不要恢复成按叶子分类统计**（会重复计数/图例出现两个 0603）。
- 刷新链路：15s `setInterval` + `focus` + `visibilitychange` + 周期切换；刷新失败必须保留上一次数据，只 `console.warn`。
- **不能改动**：`materials.inbound_at` 语义、`material_logs.action` 枚举值（borrow/restock/empty/adjust）。

## 3. 物料总览（筛选 / 排序 / 导出）

### 【面向用户：操作说明】
- **入口**：侧边栏【物料总览】。
- 顶部统计卡：物料档案总数、有货、空/待补货、低库存预警（管理员）。
- 筛选栏 4 个下拉（从左到右）：
  1. **物料状态**：全部 / 有货 / 无货 / 低库存预警；
  2. **物料分类**：只列**一级大类**（电阻、电容…），选大类会自动包含其下所有子分类物料；
  3. **封装大小**：随「物料分类」联动（选电阻只出电阻用到的封装，0402 < 0603 < 0805 自然排序）；
  4. **物料排序**：入库时间（默认）/ 库存最少 / 库存最多 / 领用最多 / 领用最少。
- 表格列：物料（封面图 + 名称 + 型号 + 封装/品牌）、分类（完整路径，如 `电阻 / 贴片电阻 / 0805`）、管理模式、库存/状态、存放位置、来源项目、入库时间、操作（详情/领用/编辑）。
- 物料名称后会显示「领用 N 次」，便于核对领用排序；顶部搜索支持嘉立创编号。
- 右下角分页；管理员可【导出 Excel】，导出内容与当前筛选/排序一致（含领用次数、分类路径列）。
- **限制**：页面数据来自一次加载的缓存（最多 500 条），超过 500 条时超出部分不参与前端筛选。

### 【面向 AI：开发维护提示】
- 前端：`frontend/index.html`、`frontend/js/materials.js`、`frontend/js/store.js`、`frontend/css/base.css`（下拉统一样式）、`frontend/css/pages.css`。
- 筛选/排序在前端缓存完成：`ERP.store.listMaterials({q, match, status, categoryIds, package, sort})`；分类过滤用 `subtreeIds()` 展开子孙分类。
- `mapMaterial` 字段映射：`borrowCount ← raw.borrow_count`、`categoryId`、`isWarn` 等；`categoryPath(id)` 基于分类树回溯。
- 后端 `GET /api/materials` 支持 `page_size ≤ 500`、`category_id` 精确过滤、`q + match` 搜索、`borrow_count` 聚合返回。
- **不能改动**：物料表字段名与类型、`store.listMaterials` 既有参数语义（其它页面可能复用）、导出行列数必须与数据列一致。
- 新增筛选条件时：先加 `store.listMaterials` 参数（保持旧默认），再加 UI 与事件，最后补手册。

## 4. 物料搜索（精确匹配 / 模糊包含）

### 【面向用户：操作说明】
- **入口**：物料总览顶部搜索框（右侧紧挨模式切换按钮）。
- **操作**：输入关键词搜索物料；**默认精确匹配**，可点击切换为模糊包含模式。
- **示例**：
  - 精确模式输入 `1K`，仅展示 1K 电阻（不会带出 91K、51K、10K 等）；
  - 精确/模糊模式输入嘉立创编号（如 `C123456`），定位对应物料；
  - 精确模式输入 `0603`，展示封装为 0603 的全部物料；
  - 精确模式输入 `电阻`，展示「电阻」分类下的全部物料；
  - 切换到模糊包含模式后，会匹配所有字段中包含 `1K` 文本的物料（如 91K、51K 也会命中）。
- **限制**：只影响搜索结果，不改动任何物料数据；搜索与筛选（状态/分类/封装/排序）可叠加使用。

### 【面向 AI：开发维护提示】
- 本搜索模块有两种查询模式：**精确匹配（默认）**、**模糊包含**。
- 前端：`frontend/js/materials.js` 的 `state.match`（`'exact' | 'contains'`）与模式切换按钮；`frontend/js/store.js` 的 `listMaterials({match})` 实现整词匹配，默认参数仍是 `'contains'`（保持旧调用方行为）。
- 后端：`GET /api/materials?q=&match=exact|contains`（`backend/app/routers/materials.py`，默认 `contains`）。精确模式实现于 `_material_exact_match / _exact_tokens`：
  - 把 code/name/model/jlc_no/package/spec/brand/cabinet/slot/source/note/**分类完整路径（如 电阻 / 贴片电阻 / 0603）** 拆成「整词」：原文本、去掉物料后缀（电阻/电容/芯片…）、去掉封装前缀（贴片/直插…）、按分隔符切分；
  - 关键词与任一整词**全等**才命中；物料总量级小（数百条），精确模式先按筛选条件取全量再 Python 过滤后分页。
- **修改规则**：精确/模糊两套规则必须**前后端保持一致**；`EXACT_SUFFIXES / EXACT_PREFIXES` 如需扩充，两处（后端 constants + 前端 store 内部数组）同步改。
- **不能改动**：原有搜索框与筛选栏 UI 组件、物料表结构、`q` 参数名；不得删除模糊包含模式。

## 5. 物料详情 / 编辑 / 删除

### 【面向用户：操作说明】
- **入口**：物料总览行内【详情】/【编辑】；详情页右上角【编辑物料】。
- 详情页展示封面图（点击看大图）、库存、预警阈值、领用次数、最近领用、规格参数等；基本信息区固定保留「嘉立创编号」，有值显示、无值留空。
- **删除物料（仅超级管理员）**：详情页 / 编辑页的【删除物料】按钮 → 二次确认弹窗（含名称/编号/型号 + 不可恢复警示）→ 确认后删除。会连带清理该物料的领用/入库流水、出入库明细，以及因此变空的出入库单。
- **限制**：删除不可恢复；删除前建议先导出或备份。

### 【面向 AI：开发维护提示】
- 前端：`frontend/pages/material-detail.html` + `frontend/js/material-detail.js`；编辑复用 `frontend/js/material-new.js`（`?id=M-xxxx`）。
- 后端：`GET /api/materials/{id}`、`PATCH /api/materials/{id}`、`DELETE /api/materials/{id}`（仅 `require_super`，`backend/app/routers/materials.py`）。
- 删除实现必须在**同一事务**内按外键顺序清理：`material_logs` → `stock_in_items` / `stock_out_items` → 空出入库单 → `materials`；`materials` 被 `material_logs/stock_in_items/stock_out_items` 以 `ON DELETE RESTRICT` 引用，**不能直接 DELETE materials**。
- 基础信息字段包含：料号 / 型号、嘉立创编号、封装、品牌、物料分类、管理模式、库存状态、来源项目、资料归属；嘉立创编号为空时条目仍保留。
- **不能改动**：删除权限（仅超管）、二次确认弹窗、级联清理顺序；不得引入物理文件删除（`uploads` 图片文件保留）。

## 6. 新增物料与图片上传（含粘贴上传）

### 【面向用户：操作说明】
- **入口**：侧边栏【新增物料】，或物料详情/列表的【编辑】按钮。
- **分类（可输入下拉）**：一/二/三级分类都是「可输入下拉」控件，两种填写方式：① 下拉直接选择已有分类；② 直接在框内打字输入分类名称；输入系统里不存在的分类，**提交物料时系统自动创建对应层级分类**（仅超级管理员可自动新建）；依旧支持一级 → 二级 → 三级逐级填写、上级变化自动联动下级。
- **限制**：分类最多 3 级；输入陌生分类名必须是超级管理员才会自动创建，普通管理员只能从下拉中选择已有分类。
- **物料图片与备注区域**：
  - 两种上传方式：① 点击【选择图片上传】；② **复制图片后，在图片区域按 `Ctrl+V` 直接粘贴上传**；
  - 限制：仅支持 jpg/png，单张 ≤ 5MB，最多 5 张；粘贴/选择走同一套校验；
  - 上传后图片自动圆角（缩略图 9px 圆角）；图片文件存服务器本地目录，数据库只保存相对路径；
  - 已上传图片可点右上角 × 移除；未上传实拍图时使用下方示意图作封面。
- 保存后自动生成档案编号 `M-xxxx`；初始库存会生成入库单与补货流水（通过本页面录入时）。
- **嘉立创编号（选填）**：位于基本信息区「料号 / 型号」下方，输入嘉立创商城物料编号；提交后可在顶部搜索框直接检索，详情页基础信息区固定展示该条目。
- **限制**：普通成员无新增/编辑入口；粘贴上传只在「新增/编辑物料」页面生效，粘贴文字不影响备注等输入框。

### 【面向 AI：开发维护提示】
- 前端：`frontend/pages/material-new.html`、`frontend/js/material-new.js`（分类级联、图片上传、粘贴、删除按钮）。
- 图片上传模块同时支持**文件选择上传 + 粘贴上传**：
  - 选择：`#materialImages` change → `addImageFiles(files)`；
  - 粘贴：`document` paste 事件 → 从 `clipboardData.items` 过滤 `kind==='file' && type.startsWith('image/')` → `addImageFiles(files)`；
  - `addImageFiles` 统一校验：最多 5 张、仅 `image/jpeg`/`image/png`、≤5MB；`ERP.api.upload('/uploads', file)` → `state.images.push(url)` → `renderUploadedImages()`；
  - 若 `event.target` 在 input/textarea/contenteditable 内，**不处理**粘贴（避免干扰文本输入）。
- 后端：`POST /api/uploads`（`backend/app/routers/uploads.py`，≤10MB，白名单 png/jpg/webp/gif），返回 `{url:'/uploads/xxx.png'}`；保存时 `material.new` 把 5 张以内路径用逗号拼接写入 `materials.image`。
- 嘉立创编号：`#materialJlcNo`（选填，maxlength=64）→ `collectPayload()` 的 `jlcNo` → `ERP.store.materialPayload()` 的 `jlc_no`；后端 `MaterialCreate/Update` 字段 `jlc_no`，序列化返回 `jlc_no`。
- 分类组件：`categoryLevel1/2/3` 为**可输入下拉（combobox）**（`frontend/js/material-new.js` + `base.css` 的 `.combo*` 样式）；`categoryChain[0..2]` 保存已选节点链，输入文本变化会清空更深层级（级联逻辑保留）；编辑时 `resolvePath(editing.categoryId)` 回填各层名称。
- **提交时解析分类**（`resolveCategoryId()`，async）：逐级读取输入文本 → 匹配已选节点/同级已有分类 → 仍不存在时：超管调用 `ERP.store.addCategory(name, 父级id|null)`（即 `POST /api/categories`）自动创建，普通管理员返回「分类不存在，仅超级管理员可新建分类」；新建两级时父级逐级链接。**自动创建只发生在提交时**，打字过程不调接口。
- **不能改动**：分类/物料表结构、`POST /api/categories` 接口契约、原有表单校验顺序、最多 3 级、编辑回填逻辑。
- **不能改动**：图片存储路径（`UPLOAD_DIR=/app/uploads` → 宿主机 `data/uploads`）、数据库 `materials.image` 字段结构、上传接口白名单/大小上限、5 张上限、圆角样式（`.uploaded-item` 9px）。
- 新增上传方式时必须复用 `addImageFiles`，不得另起一套校验或存储逻辑。

## 7. 分类管理（树形多级 + 末级物料列表）

### 【面向用户：操作说明】
- **入口**：侧边栏【分类管理】。
- 树形分类支持多级（示例：电容 → 贴片电容 → 0603；电阻 → 贴片电阻 → 0805），每级右侧实时显示**该分类下物料总数**（含子分类合计）与本级数量。
- 展开/折叠箭头可查看子分类；一级/二级/三级字号依次递减，便于分辨层级。
- **分类树【新建分类】按钮**（超级管理员）：分类树区域右上角【新建分类】——**未选中任何分类时**创建一级分类；**先选中某条分类再点**，则为该分类添加子分类；创建成功分类树自动刷新，并自动选中新分类（展开其上级）。
- **末级分类物料列表**：点击/选中**最后一级子分类**（如 电阻→贴片电阻→0805），页面下方自动加载该分类下的全部物料列表：
  - 列表样式与「物料总览」一致（封面图、名称、分类路径、管理模式、库存/状态、存放位置、来源项目、入库时间、操作：详情/领用/编辑）；
  - 支持分页查看；切换其他分类时列表自动刷新到第一页；
  - 上级（非末级）分类不会展示物料列表，会提示先选末级分类。
- **超级管理员**：右键任意分类 →【新建子分类】【删除当前分类】；重命名按钮。
- **删除限制**：分类下有子分类时不能删；分类（含子分类）下还有物料时**禁止删除**并提示数量，防止丢数据。
- **限制**：删除/新增/重命名分类仅超级管理员；折叠状态只保存在当前页面内存。

### 【面向 AI：开发维护提示】

## 14. 数据库备份（超管）

### 【面向用户：操作说明】
- **入口**：侧边栏【管理 → 数据库备份】，仅超级管理员可见、可用。
- **用途**：把当前 MariaDB 全量导出为独立 `.sql` 文本快照，并可把选中的快照提交、推送到**与 ERP 源码仓库完全独立**的私有 Git 仓库。树莓派 SD 卡或硬件损坏、甚至无法登录原服务器时，只要还能访问该私有仓库，就能在任意电脑上取回备份、恢复全部物料台账。
- **首次配置**：
  1. 在 GitHub（或其他 Git 服务）新建一个**空的私有仓库**，专用于数据库备份，不要复用 ERP 源码仓库；
  2. 打开本页，复制页面上的“专用部署公钥”，到该仓库的 Settings → Deploy keys 添加，并勾选 **Allow write access**；
  3. 填写仓库 SSH 地址（如 `git@github.com:用户名/linda-erp-db-backup.git`），点【保存配置并预检】；
  4. 预检全部通过后，再执行导出/推送。
- **导出**：点【导出数据库备份】，生成 `linda_erp_YYYYMMDD_HHMMSS.sql`，保存在树莓派独立目录 `/home/lin/erp_db_backup`。
- **推送**：在“本地备份文件”列表中选择未推送的文件，点【推送】，系统自动 `git add / commit / push`；提交信息包含备份时间和文件名。
- **列表与恢复**：列表展示备份时间、大小、提交状态（未提交 / 已提交待推送 / 已推送）与提交号；页面底部提供完整恢复命令和注意事项。
- **限制**：只保存 `.sql` 文本快照，绝不复制 MariaDB 原始数据文件；导出、推送、配置变更都会记录操作人、时间与结果。普通管理员和成员看不到本页，后端也会返回 403。

### 【面向 AI：开发维护提示】
- 前端：`frontend/pages/backup.html`、`frontend/js/backup.js`；导航项在 `frontend/js/config.js` 的“管理”组，`roles: ['super']`；页面样式在 `frontend/css/pages.css` 末尾“v1.8.0 数据库备份”区块。
- 后端：`backend/app/routers/backup.py`，统一前缀 `/api/admin/backup`，所有接口 `Depends(require_super)`：`GET /status`、`PUT /config`、`GET /list`、`POST /export`、`POST /push`、`GET /logs`。
