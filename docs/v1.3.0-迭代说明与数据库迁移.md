## 一、本次迭代内容

### 1. 顶部标题 & Logo 自定义（仅超级管理员）
- 侧边栏主标题【硬件物料台账】、副标题【校内硬件社团】**双击即可就地编辑**，回车/失焦保存、Esc 取消，写入数据库 `site_settings`。
- Logo 图标支持上传图片（png/jpg/webp/gif ≤5MB），上传后**自动圆角 7px**，与默认内置图标圆角一致。
- 右上角退出按钮改为弹出选择框：**【退出登录】/【前往封面编辑】**（后者仅超级管理员可见）。
- 新增封面编辑页 `pages/cover.html`：`cover_title / cover_slogan / cover_footer / app_name / club_name` 全部支持双击编辑并持久化；右下角【返回主页面】按钮仅封面编辑页显示。

### 2. UI 与 BUG 修复
- **统计周期下拉框**：去原生箭头，改为固定尺寸 + 自定义 SVG 箭头 + 统一内边距，箭头/文字/外框居中对齐。
- **进出物料趋势图**：修正统计口径 —— 原来只统计 `material_logs`（领用/补货流水），直接写入的物料没有流水导致图表恒为 0；现改为
  - 入库 = `materials.inbound_at`（物料建档入库）+ 真实补货流水（排除新增物料时自动生成的初始库存流水）
  - 领用 = `material_logs.action='borrow'`
  - 保留 15 秒轮询 + 回到页面刷新；当前 259 条物料会正确显示在当天入库曲线上。

### 3. 分类管理改造为树形多级分类
- `categories` 表新增 `parent_id`（一级分类为 NULL）。
- 分类管理页树形渲染：层级缩进、展开/折叠，**每一级右侧实时显示该分类下物料总数（含子分类合计）**。
- 超级管理员在任意分类行**右键**弹出菜单：【新建子分类】【删除当前分类】。
- 新建子分类弹窗输入名称（同级重名拦截）。
- 删除校验：**有子分类或子树内仍有物料时禁止删除**，弹窗提示数量，防止丢数据。
- 已删除的分类不会留下孤儿物料（外键 RESTRICT）。

### 4. 物料删除（仅超级管理员）
- 物料详情页 / 编辑物料页新增【删除物料】按钮。
- 点击弹出**二次确认弹窗**：展示物料名称/编号/型号，明确提示「删除后不可恢复；领用/入库流水与出入库单明细会一并删除」。
- 后端在同一事务内清理 `material_logs` / `stock_in_items` / `stock_out_items`，并清理因此变空的出入库单，再删除物料档案。

### 5. 权限
所有新增/编辑/删除/右键菜单均为**超级管理员**专属：后端 `require_super` 强校验，前端非超管不渲染入口。

## 二、数据库迁移方案（重点）

**原则：原库 `linda_erp` 的结构与数据一字不动，全部迁移到新库 `linda_erp_v2`。**

| 项目 | 说明 |
| --- | --- |
| 旧库 | `linda_erp`（v1.2.6，保留原样，未做任何 ALTER/DROP/DELETE） |
| 新库 | `linda_erp_v2`（v1.3.0 结构） |
| 结构变化 | `categories` 增加 `parent_id`；新增 `site_settings`；其余表结构不变 |
| 数据迁移 | 全量复制并保留原 id：users 3、categories 11、materials 259、user_visits 23、出入库单/明细/流水 0（当时为空） |
| 迁移脚本 | `db/migrations/20261123_v130_new_db.sql` |
| 业务账号 | 沿用 `linda_erp`，迁移脚本内追加 `GRANT ... ON linda_erp_v2.*` |
| 切换方式 | 部署目录 `.env` 的 `DB_NAME=linda_erp_v2`，重建后端容器 |
| 回滚方式 | `.env` 改回 `DB_NAME=linda_erp` 并重启后端容器即可（旧库数据完好） |

## 三、新增/变更接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/settings` | 登录 | 读取站点配置（标题/社团名/Logo/封面文案） |
| PATCH | `/api/settings` | 超级管理员 | 修改站点配置 |
| GET | `/api/categories` | 登录 | 分类列表：`items`（扁平）+ `tree`（嵌套），含 `count/total_count` |
| POST | `/api/categories` | 超级管理员 | 新增分类，支持 `parent_id` 建子分类 |
| PATCH | `/api/categories/{id}` | 超级管理员 | 重命名 |
| DELETE | `/api/categories/{id}` | 超级管理员 | 删除（有子分类/有物料时 409 拦截） |
| DELETE | `/api/materials/{id}` | 超级管理员 | 删除物料并级联清理关联流水/明细/空单据 |
| GET | `/api/dashboard/summary` | 登录 | KPI 与趋势（口径已修正，新增 `new_material_count/restock_count`） |

## 四、部署与验证

1. 上传 `backend/app`、`db/migrations`、`docker-compose.yml`（镜像标签 `linda_erp-backend:1.3.0`）、`frontend/`。
2. 执行迁移脚本（见上）。
3. `.env` 增加 `APP_VERSION=1.3.0`、`DB_NAME=linda_erp_v2`。
4. `docker compose build backend && docker compose up -d backend`（前端为静态挂载，上传即生效）。
5. 校验：`/api/health` 返回 `version: 1.3.0`、`database: ok`；`/api/dashboard/summary?period=month` 入库 = 259。
